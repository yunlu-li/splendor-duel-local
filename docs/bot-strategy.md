# 机器人策略实现

本次采用参考包的策略原则，并复用本项目的卡表、GameAction 和规则引擎。

## 使用

进入“与机器人对战”，在顶部“难度”选择“竞技”或“休闲”。默认竞技，可在对局中切换。
机器人行动后显示简短理由。计算在 Web Worker 内执行；重开、关闭机器人、切换模式或难度会取消旧计算。
玩家的“执行建议”保留轻量提示，其实现位于 `src/client/coach/suggestion.ts`，与机器人策略独立。
机器人模式固定玩家身份为 P1，机器人为 P2；机器人回合禁止人工执行主行动、特权或特殊选择。面板、提示和保留日志均隐藏对手暗牌内容。
计算超过 30 秒或启动失败时，终止后台线程并显示“重试机器人”，保留当前棋盘。
当前只开放本地双人和机器人模式。好友房代码暂存，页面没有联机入口，也不会自动处理旧邀请链接。

## 文件与调用关系

| 文件 | 责任 |
| --- | --- |
| `src/shared/bot/chooseAction.ts` | 总入口，返回 action、explanation、score、phase、factors |
| `src/shared/bot/observation.ts` | 清理隐藏信息，为未知内容建立仅依赖公开信息的可复现样本 |
| `src/shared/bot/legalActions.ts` | 枚举合法行动、连续线段、支付方案及所有特殊选择 |
| `src/shared/bot/evaluate.ts` | 分阶段状态评分、目标卡缺口、资源价值、棋盘余留风险 |
| `src/shared/bot/phase.ts` | 开局、中盘、终局判断 |
| `src/shared/bot/resolveChoice.ts` | 在规则引擎中继续结算卡牌能力、皇室选择、弃牌 |
| `src/shared/bot/threats.ts` | 对手公开市场获胜威胁，包括先花特权补齐资源的购买 |
| `src/shared/bot/config.ts` | 颜色、等级和分阶段评分权重 |
| `src/shared/bot/explain.ts` | 用实际评分增量生成中文说明 |
| `src/shared/bot/outcome.ts` | 统一直接行动与可选行动后主行动的额外回合、盲保调整 |
| `src/client/workers/bot.worker.ts` | 浏览器后台计算入口 |
| `src/client/gameAccess.ts` | 人工操作权限、当前行动者与本地查看者身份 |

每次决策先建立可见状态，然后枚举并筛选候选，用 `applyAction()`模拟。能力、皇室卡与弃牌完成后才判断胜利。
模拟采用克隆状态，不改变真实对局。人工动作通过权限检查后提交，机器人结果通过内部执行入口提交；两者均由 `applyAction()`校验。
规则入口校验动作结构和资源整数数量，特殊关联选择校验目标与颜色。补盘按 seed 和 `refillCount`重新混合袋内宝石，支持重放。
卡表与好友房协议保持不变，依赖版本固定为当前已验证版本。

## 策略

1. 自己立即获胜的购买或特殊选择优先。
2. 有公开获胜威胁时，优先避免把回合交给仍能获胜的对手。预留关键牌、购走关键牌、偷取等动作通过模拟结果判断是否有效。
3. 普通局面使用威望、王冠、单色威望、与市场需求匹配的折扣、购买距离、资源和保留槽负担综合评分。
4. 王室奖励通过实际结算进入评分，考虑达到或跨越 3/6 冠。
5. 珍珠没有永久折扣；黄金能补齐珍珠和普通宝石。枚举可保留珍珠/关键宝石的黄金支付方案。
6. 特权取珠和补盘与其后主行动一起比较，计入赠送对手特权的实际成本。
7. 对同色取珠位置和高分候选比较留给对手的连续线。弃牌尽量保留目标卡所需资源。
8. 额外回合给予机会价值，直接购买与特权/补盘后购买统一计分；盲保扣分同样按最终主行动统一计算，后续行动在新状态下重新决策。

开局权重偏向有效折扣；中盘提高得分与王冠价值；终局提高直接得分与单色路线价值。
任一方威望达到 15、王冠达到 7 或单色威望达到 7 时进入终局。
一次决策内保持同一组权重，包括深层弃牌排序，避免候选恰好跨阶段造成评分跳变。评分明细包含额外回合、盲保、可选行动与棋盘风险调整，其总和对应返回的相对分数。

休闲从分数接近的前四个候选中做可复现的随机选择，保留立即获胜和避免公开败局的优先级。
竞技按最高分选择，并比较前八个候选的棋盘风险。

## 搜索边界与公平性

合法动作枚举与搜索裁剪分开。所有购买方案均参与比较；经济分支保留八条取珠线和四个预留候选。
终局保留全部公开预留动作，防止关键封锁被经济剪枝移除。
特权按颜色选取代表位置做经济前瞻，其他位置仍检查随后能否购买；深层弃牌先对分配进行评分，再结算前六个。

当前前瞻为一次可选行动加主行动及其能力结算。没有 MCTS、完整多回合对手回复搜索或训练模型。
多个特权和额外回合可连续执行，但每一步都从最新状态重新规划，尚不保证找出整条最优连锁。

决策前清空原始 seed 和 log，移除对手保留牌内容，以公开卡表减去已知牌后采样未知牌堆；袋内顺序也重新采样。
采样种子仅依赖公开状态、机器人自己的手牌与公开数量。改变真实暗牌或真实牌序不会改变决策。
补盘收益使用一个公开信息样本估计，其获胜结果不会被当作必胜保证。
威胁检测只涵盖当下公开市场与特权补齐购买，不声称能准确预测未知预留卡或所有额外回合连锁。
在线房间的隐藏信息传输属于独立问题，本次没有改变服务器公开视图。

## 验证命令

```sh
npm test
npm run build
npm run test:bot -- 1000 8
npm run test:bot-ui
```

运行环境统一为 Node.js 24.x。
`test:bot` 的两个参数是局数和工作线程数。种子固定，每四局包含新旧策略先后手各一局，以及竞技/休闲对战各一局。
每次行动检查代币、特权、67 张宝石卡的数量与唯一性；超过 600 次原子动作未结束记为失败，不会计为获胜。
输出分组胜负、胜利路径、动作数、决策耗时和失败种子。旧策略仅保存在测试辅助文件中，不参与产品运行。
浏览器测试验证两个可用模式、旧邀请链接停用、无好友房网络连接、实际后台线程行动、人工权限与暗牌保护、中文理由、模式切换取消和失败重试；可用 `BOT_TEST_BROWSER`指定浏览器路径。

## 初版历史基线（2026-10-19，补盘与评分修复之前）

以下数据来自初版实现，不作为当前修复版本的胜率或稳定性结论。当前版本的补盘随机性与完整行动评分已发生变化。

- `npm test`：3 个测试文件、28 项测试通过。
- `npm run build`：TypeScript 检查与 Vite 生产构建通过，包含独立 worker 资源。
- 浏览器检查：休闲/竞技实际自动行动、中文理由、模式切换取消均通过，无浏览器脚本错误。
- 1000 局批量对弈全部正常结束，共执行 87,930 次原子动作；没有非法动作、守恒错误或超过 600 动作上限的失败。

| 对战分组 | 对局数 | 新策略/竞技获胜 | 胜率 |
| --- | ---: | ---: | ---: |
| 新策略对旧策略，新策略先手 | 250 | 238 | 95.2% |
| 新策略对旧策略，新策略后手 | 250 | 240 | 96.0% |
| 竞技对休闲，交替先后手 | 500 | 378 | 75.6% |

这是固定种子的程序对战基线，不代表对人类玩家的胜率。整组对局覆盖总威望、王冠和单色威望三种胜利路径。
8 线程并发测试中共执行 68,061 次新策略决策，平均约 92.5 毫秒，最长约 9 秒；耗时包含并发资源竞争，不能视为所有设备上的响应保证。
复杂局面仍可能思考较久，因此浏览器采用后台线程，计算期间页面保持响应。
